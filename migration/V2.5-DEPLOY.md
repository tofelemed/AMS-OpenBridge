**The traps, in order of cost:**

1. **Source tree before scripts.** The bundle used to ship images only. With the old tree, 04 creates no new
   topic, 04b submits four jobs, the compose files start JM/TM without the signing key, and 05 reads green.
   Extract the archive first (C1) and run the two greps.
2. **Schema before image.** The new cplm-api consumers write columns and tables that only cpm-07 creates. The
   image self-heals only the pre-v2.5 tables. cpm-07 → cpm-07b → cpm-08 → cpm-09 → ownership, then images.
3. **Ownership after schema.** The SQL files run as `postgres` (they create extensions), so the new tables are
   postgres-owned; cplm-api's self-heal DDL then fails with 42501 and its consumers never join — the go-live
   bug. `02-apply-schemas.sh` sentinel-skips every DDL file and normalizes ownership on all five databases.
4. **Topics before jobs.** The plant broker has auto-create off. A CPLM job whose sink topic is missing fails
   at its first record; the Response job announces its capability on the ACK topic at start.
5. **The signing key.** Without `CPLM_GATE_CONFIG_KEY` on the TaskManager nothing breaks, but every
   configuration bundle is NACKed `UNSIGNED` and no deployment can ever be verified. Prove it (C7).
6. **Every CPLM job is resubmitted.** Operator chains changed: no savepoint restore. Short windows rebuild
   within the hour; 12 h / 24 h verdicts need up to a day.
7. **cpm-07b runs with cplm-api stopped.** Old consumer needs the old unique key, new consumer the new one.
   Results queue in Kafka from the stop to C6. If cpm-07b fails half-way, re-run it (every statement is
   `IF NOT EXISTS` / `IF EXISTS`).
8. **`deploy.sh` needs the env.** `ALLOW_FLINK_SUBMIT=yes` or 04b never runs; `START_AMS_API=yes` or compose
   drops ams-api (the only writer of the loop historian) from its scope; `ALLOW_CREATE_PREFIXED_TOPICS=yes` or the
   final 05-validate only warns about missing topics. `migration/.env` is sourced after these exports (`set -a`),
   so an uncommented `ALLOW_*=no` line in it would win - keep those lines commented.
9. **The overlay leaves the checkout showing the delta.** `/opt/AMS-open` is a git checkout; after C1 `git status`
   lists the release's files as modified until the plant's checkout is moved to that commit. `RELEASE-COMMIT` names
   the commit the tree is; the next release overlays again. Never `git checkout -- .` on the VM after C1.
10. **A CPLM job that sits in RESTARTING with `FLINK-25920`.** Found on the lab the evening before the tag: a job
   restored from the checkpoint that closed its capability-announce task (chk-1 of a fresh submission) failed with
   `UnsupportedOperationException … CommittableSummary … FLINK-25920` on every restart, for ever. v2.5 ships the fix
   (the announce source never ends), so it should not appear. If any job ever does: Flink UI → the job → Exceptions
   names it; 04b counts RESTARTING as present and will not resubmit, so `flink cancel <jid>` that one job (from the
   JM container), then re-run 04b - it submits only what is missing. 05-validate warns on RESTARTING.

## E. Afterwards, not part of the release

- **Transmitter health** stays `NOT_CONFIGURED` until Instrumental delivers its NE107 publisher; then one
  `INSTRUMENTAL_HEALTH` data source per publisher (`docs/next-release/instrumental-health-contract.md`) and
  device bindings per loop / role (`POST /loops/{id}/instrument-bindings`). By design, not a defect.
- **Governed configuration** starts empty: every loop runs the factory layer (= the class packs, exactly as
  before) until a site activates a bundle. The first activation of a scope has no previous bundle to roll back to.
- **Retention** of the result tables is still an ops decision (`ops/cpm-05-gate-results-retention-check.sql`);
  evidence chunks expire by record class (STANDARD, set to 7 d in C3b; PINNED never) and the expired rows are purged
  after `Cplm:EvidenceExpiredGraceDays` (7) more days. Watch `pg_total_relation_size('analytics.evidence_chunk')`,
  `pg_total_relation_size('analytics.evidence_manifest')` and `df -h /` daily for the first two weeks; the cplm-api log
  line "Evidence retention: … expired, … purged" must appear once a day from day 8.
- **Metaspace rule** (readiness gap G3): no more than ~10 shadow / replay / reconstruction runs between TM
  recreates; watch `flink_taskmanager_Status_JVM_Metaspace_Used` in Prometheus.
- `--evidence-emit` (EPISODES by default) and `--g12-delay-min-s` are job args on the Response / engine jobs
  (`migration/04b-submit-flink-jobs.sh`).

## Rollback

Schema is additive — leave it (the old images ignore the new columns and tables). The extracted source tree can
stay too: the old images run under the new compose files, and 04b's three extra submissions fail on the old jar
(no entry class) — expected, cancel nothing else. Reload the previous images from `/tmp/pre-v2.5-images.txt`
(`docker tag <old id> <name>`), restore the previous JAR, `docker rm -f ams-flink-taskmanager ams-flink-jobmanager`,
`deploy.sh --prod`. The eight new topics and the new permissions can stay.

**cplm-api is the one exception.** Its old consumer upserts `ON CONFLICT (loop_id, window_kind, window_end,
source)`, the key cpm-07b replaced. Before starting the OLD cplm-api image, restore that key with cplm-api stopped:

```sql
-- traverse_cplm, cplm-api STOPPED. Fails if v2.5 wrote a second row for one window under another bundle
-- (a re-evaluation); delete those rows first: DELETE FROM analytics.cplm_gate_results WHERE bundle_hash <> 'legacy' AND purpose <> 'LIVE';
CREATE UNIQUE INDEX IF NOT EXISTS uq_cplm_gate_results_window ON analytics.cplm_gate_results (loop_id, window_kind, window_end, source);
CREATE UNIQUE INDEX IF NOT EXISTS uq_cplm_short_window ON analytics.cplm_short_feature_results (loop_id, window_kind, window_end, source);
CREATE UNIQUE INDEX IF NOT EXISTS uq_cplm_long_window ON analytics.cplm_long_feature_results (loop_id, window_kind, window_end, source);
```

The simpler rollback is to keep the v2.5 cplm-api (it reads and writes pre-v2.5 rows as `legacy`) and roll
back only the jar / ingestion / frontend / historian-bff.
