# v2.3 — disk cleanup, transfer, deploy

Combined release: **v2.1 + v2.2 in one window.** Five services, the Flink JAR, and a job
resubmission. Deploy this *instead of* v2.1 and v2.2, not after them.

| | |
|---|---|
| Bundle | `release-out/v2.3-20260912/` |
| Services | `ams-api`, `flink-jobmanager`, `historian-bff`, `ams-frontend`, `traverse-ingestion-service` |
| Schema change | none |
| Data load | none — the MODE map and CPM onboarding were one-time v3 actions, already done |
| VM | `lean@192.168.190.91`, repo at `/opt/AMS-open`, compose project `ams-cpa` |

**Two traps, both of which report success while doing nothing.** They are the reason this
document exists; everything else is routine.

1. **Flink** — `04b-submit-flink-jobs.sh` uses `submit_if_missing`. With the old JobManager
   still up it prints `[OK]` for all four jobs while they keep executing the **old jar**.
   Removing *both* Flink containers is mandatory.
2. **ams-api** — it sits behind `profiles: ["cpa-ams-api"]` and `deploy.sh` adds that profile
   only when `START_AMS_API=yes`. Without that export, compose loads the new image and leaves
   the **old container running**. It is the only writer of `root.site1.cpm.*`, so the no-op is
   invisible until a trend goes missing.

## A. Disk cleanup (do this first, on its own)

The host has filled three times. A `docker load` with no room corrupts more than it deploys.
Target **≥ 8 GB free** before transferring.

### A0. Measure before deleting

```bash
ssh lean@192.168.190.91
df -h /
sudo du -xh --max-depth=1 / 2>/dev/null | sort -rh | head -15
docker system df
```

### A1. Old release bundles in /tmp

List first, delete only what you recognise:

```bash
du -sh /tmp/* 2>/dev/null | sort -rh | head -20
```

```bash
rm -rf /tmp/v3 /tmp/v3-* /tmp/v4 /tmp/v4-* /tmp/v5 /tmp/v5-* /tmp/v2.1 /tmp/v2.1-* /tmp/v2.2*
rm -f /tmp/pre-v*-images.txt
```

### A2. Flink down + its volumes (~5 GB)

The deploy removes both Flink containers anyway, so bring them down **now** and leave them
down until step C4. Jobs come back with fresh window state either way.

```bash
docker rm -f ams-flink-taskmanager ams-flink-jobmanager
docker volume ls | grep flink
docker volume rm ams-cpa_flink-jm-tmp ams-cpa_flink-tm-tmp ams-cpa_flink-jm-log ams-cpa_flink-tm-log
```

Compose recreates all four on the next `up`. If `volume rm` says *volume is in use*, a Flink
container is still alive — re-run the `docker rm -f` above.

### A3. Orphaned checkpoints in MinIO (~9 GB — the big one)

`RETAIN_ON_CANCELLATION` plus repeated resubmits left a checkpoint tree per abandoned job:
868 MB → 9.1 GB in two days. With Flink down (A2), the whole tree is dead weight.

```bash
docker exec ams-minio du -sh /data/ams-flink/* 2>/dev/null
```

```bash
docker exec ams-minio sh -c 'rm -rf /data/ams-flink/checkpoints/* /data/ams-flink/savepoints/*'
docker restart ams-minio
docker exec ams-minio du -sh /data/ams-flink 2>/dev/null
```

MinIO stores each object as a self-contained directory and lists by walking the filesystem, so
removing whole subtrees leaves nothing dangling. `.minio.sys` is untouched.

**Permanent fix, already in the repo:** the marun overlay sets
`execution.checkpointing.externalized-checkpoint-retention: DELETE_ON_CANCELLATION`
([docker-compose.marun.yml:285](deploy/docker-compose.marun.yml#L285)). It travels with this
release and takes effect when the Flink containers are recreated in C4 — so this cleanup
should not be needed again.

### A4. Container logs — truncate, never delete

Deleting a live container's json-log breaks its logging until restart.

```bash
docker ps --format '{{.Names}}' | while read -r c; do
  f=$(docker inspect --format='{{.LogPath}}' "$c")
  [ -n "$f" ] && [ -f "$f" ] && sudo truncate -s 0 "$f" && echo "truncated $c"
done
```

### A5. systemd journal

```bash
sudo journalctl --disk-usage
sudo journalctl --vacuum-size=200M
```

### A6. Dangling images only

Never `docker system prune`, `prune -a`, or `volume prune`. Never `docker rmi -f`. On an
air-gapped host image removal is a one-way door — nothing can be re-pulled.

```bash
docker images -f dangling=true          # read the list before the next line
docker rmi $(docker images -f dangling=true -q)
```

### A7. Confirm

```bash
df -h /
```

Do not proceed under 8 GB free.

**Run from Git Bash, not PowerShell** — a PowerShell pipeline corrupts binary streams, and
`C:\...` is parsed as a hostname by `scp`. Use `/d/...` paths.



## D. Post-deploy checks

### D1. ams-api actually restarted (trap 2)

```bash
docker inspect -f '{{.Created}} {{.Image}}' ams-api
```

`.Created` must be **today**. If it is not, the profile export was missed — re-export
`START_AMS_API=yes` and re-run `deploy.sh --prod`.

Then confirm the historian is writing, and that CHG-020 is the code that is running:

```bash
docker logs --since 10m ams-api | grep -c 'wrote .* samples'
docker logs --since 10m ams-api | grep -iE 'rejecting every write|poison'
```

The first should be non-zero. The second should be **empty** — if it prints the stall message,
IoTDB is refusing writes and the consumer is now correctly holding its offsets rather than
discarding, which is the whole point of CHG-020. Investigate IoTDB disk before anything else.

### D2. Flink

```bash
docker exec ams-flink-jobmanager flink list -m localhost:8081
```

4 × RUNNING, start times moved.

### D3. historian-bff — the new endpoint exists

```bash
export ADMIN_PW='...'
TOKEN=$(curl -s -X POST http://localhost:8081/api/auth/login -H 'Content-Type: application/json' \
  -d "{\"username\":\"admin\",\"password\":\"$ADMIN_PW\"}" \
  | python3 -c "import sys,json;d=json.load(sys.stdin);print(d.get('accessToken') or d.get('token'))")
echo "len=${#TOKEN}"
```

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  'http://localhost:8081/api/hist/last?series=root.site1.cpm.PIC80105&measurements=pv,sp,op,mode' | head -c 400; echo
```

Expect a value **and a per-measurement timestamp** for each. A 404 means the old bff is still
running — the frontend's Summary tab will show a blank tile per loop until it is replaced.

Login is rate-limited to **10/min/IP**; mutations to **120/min globally**. Tokens expire in 1 h.

### D4. ingestion-service

```bash
curl -s http://localhost:8081/api/ingestion/stats | python3 -m json.tool | head -30
```

Check `paramRoles.VP == "vp"` and the restored-loop count. Read it from the API, **not** the
startup log — the plant runs `SERVICE_LOG_LEVEL=Error`, which suppresses it.

### D5. Frontend

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8090/
```

200, then **Ctrl+F5** in the browser. On Loop Explorer › Summary, a loop whose SP has not moved
should now read `last stored …` with an age rather than `—`, and MODE should carry a source
suffix.

### D6. Disk, again

```bash
df -h /
docker exec ams-minio du -sh /data/ams-flink 2>/dev/null
```

The checkpoint tree should now stay small — `DELETE_ON_CANCELLATION` is live from C4.

## E. Rollback

Images are still on the host (nothing was `rmi`'d), listed in `/tmp/pre-v2.3-images.txt`.

```bash
docker tag <old-image-id> <repo>:<tag>
export START_AMS_API=yes
bash migration/deploy/deploy.sh --prod
```

For Flink, `docker rm -f` both containers first or the resubmit will report `[OK]` against the
jar that is already running.

**Not rollback-able:** window state. Jobs restarted fresh in C4 either way, so a rollback does
not restore 12 h / 24 h verdicts any faster than going forward.
