# prod_decision.md — the production settings of record (Marun, CPA / loop performance)

Why this file exists: the plant runs on a shared host with settings that are the result of incidents,
measurements and deliberate trade-offs. If this application is deployed on another server, every value
below must be decided again for that server, and this file says what we chose here and why. Keep it
current with every release (`changes_tracker.md` CHG entries are the history; this file is the state).

Last updated: 2026-10-10 (**v2.7.0 live at Marun since 2026-10-10 09:17 UTC**: SME batch + CHG-049/060-062/068/075/076; values formerly marked "deployed 2026-10-10, v2.7.0" are now live; v2.6.6 / CHG-039 since 2026-10-05; cpm-12/12b/13 applied 2026-10-10).

| Evidence, episode captures (`EPISODE`) | `analytics.retention_policy` row `EPISODE` | **2 days** after the episode closed (was 90; cut 2026-10-02), unchanged by CHG-049, never while it is open | `ops/cpm-10a-episode-evidence.sql` | the user's design: evidence follows the episode, captured at OPEN / ESCALATE / CLOSE (`Cplm__EpisodeCaptureMax` = 3 automatic captures, CLOSE always) |
| Evidence, reconstructions (`STANDARD`) | row `STANDARD` | **3 days** (shipped 90; cut at the go-live disk survey) | `retention_policy` | an operator-requested rebuild is cheap to redo |
| Evidence, pinned (`PINNED`) | row `PINNED` | never | `retention_policy` | investigation references |

## 4. Engine and pipeline settings

| Setting | Value | Why |
|---|---|---|

| G0 completeness | expected samples from the declared `grid_seconds`, not the median interval | patch 1: the median of whole-second intervals gave 4 or 6, never 5 |
| ZooKeeper (Instrumental's) | 3.8.x (`cp-zookeeper:7.5.0` at Marun, 7.5.3 on the lab), affected by ZOOKEEPER-2332; start guard CHG-068 live since 2026-10-10 (`zk-start-guard.sh` + `zookeeper-start-guard.override.yml` in `/opt/Instrumental-pro-sis/microservices`, project `microservices`) | a zero-byte txn log after a full disk crash-looped it twice; upgrade to >= 3.9.3 is a later item |
| Short Feature job parallelism | `CPLM_SHORT_PARALLELISM=4` (16 slots; 9 were free) | one core could not keep six sliding windows over 142 loops current (v2.6.5 design: ~22 real samples/s per core; with v2.6.6 ~650/s per core, so 4 is headroom, not a need) |
| Short Feature job windowing | v2.6.6 (CHG-039): ONE keyed operator holds each loop's samples once and fires 1m / 5m / 10m / 15m / 30m / 60m from that buffer with Flink's window semantics (same sizes, slides, lateness, identical output). v2.6.5 ran six window operators storing every sample 32 times | the six-operator design drained a backlog at ~22 real samples/s per core (a 1.46 M backlog ≈ 7 h at Marun); the buffer does ~650/s (~30×, bench in CHG-039), state written once per sample, one timer chain per loop. Keep any new window kind inside `ShortWindowSpecs`, never as a new sliding `WindowOperator` |
| Short job state backend | v2.6.6 (CHG-039): **heap** (`HashMapStateBackend`, set by the job itself; all other jobs stay on RocksDB). ## 7. Deploying to another server: what to decide again

1. Disk: an own volume for our Docker volumes (item 1 of the remediation document); size it from the rates in section 3 times the days wanted.
2. `migration/.env`: every `CPLM_*` value above, `CPLM_GATE_CONFIG_KEY`, the Kafka bootstrap and container names (`migration/lib.sh` defaults are Marun's).
3. The `retention_policy` rows (section 3) and the `Cplm__*` values: set them for that disk BEFORE switching evidence on.
4. Kafka topic retention (`topics.txt`) and `04c-apply-topic-retention.sh`; whether TimescaleDB exists (if it does, `39_timescale_policies.sql` instead of cpm-10b).
5. The OT payload contract (`quality_protocol`, `event_ts_ms`, `grid_seconds`) and the loop model (`command_path`).
6. Cron: `migration/cron.d/cpa-capacity` (log caps); monitoring (the observability profile is off at Marun; remediation item 4).
7. Flink sizing: TaskManager memory (3.5 GB for 16 slots at Marun since v2.6.6; the Short job's heap buffer grows with loops × samples per hour), `CPLM_SHORT_PARALLELISM`, and the daily check's checkpoint thresholds (1.5 / 3 GB for ~150 loops; scale with the loop count). Measure a backlog drain on that host before go-live (`ShortWindowBacklogBench -Dshort.bench.real=true`, CHG-039). If a much larger plant (thousands of loops or 1 s grids) outruns it, the next lever is a bounded heap cache of decoded samples in `ShortFeatureBufferFn` (reads are the remaining cost; it needs task-heap budget, ~150–200 MB at Marun's size).
8. Evidence volume: decide `CPLM_EVIDENCE_MAX_CYCLES` and `CPLM_EVIDENCE_MIN_INTERVAL_MIN` by loop count and window cadence (Marun: 12 and 60). Then measure the evidence tables' physical size (`pg_total_relation_size`, not the payload sum) after 24 h and set the daily check's thresholds from it (1536 / 3072 MB here).
9. ZooKeeper on a shared host: know the recovery rule before the first full disk (`migration/MARUN-DISK.md` section 3 J): back up, then MOVE a zero-byte `log.*` out of `version-2/`, never rename or delete the data directory.
