Below review is mainly about normal user workflow and how information is presented. Analytical Information is improving, but overall app still feels difficult to use.
Good part is that app now has useful evidence plots, calculation details, window information and method references. These should remain available. Problem is user has to do too much searching to understand one loop.
Navigation is organised around internal analysis functions. Evidence Replay, Evidence Workbench, Investigation, Window Inspector and Calculations are separate pages, but purpose and difference are not immediately clear. Need organise main flow around user tasks: find problem, check loop, understand cause and record action.
Loop selection is not consistently carried between pages. Some direct buttons carry selected loop, but opening another page from menu can ask to select again. Same loop, plant scope and applicable time period should remain selected until user changes them.
Need persistent header showing current loop, service, location and selected window. On long pages this context goes out of view. User should always know which loop and period he is checking.
Main loop page should show short summary first: current condition, severity, diagnosis, important evidence, data availability and next checking action. Currently these are scattered between badges, gate panels and lower sections.
Overview is giving too much space to missing positioner feedback and configured peers, while basic operating picture is incomplete. Need clearly show healthy, poor performance, excluded, stale and not evaluated loops. Configuration limitations can remain in separate readiness section.
“Need attention 141” also says “141 loops evaluated”. Need explain if all evaluated loops actually need attention or both counts are being mixed. Excluded mode, missing data and confirmed abnormal performance should not all look like same type of problem.
Priority queue showing several loops with same 100% confidence, but performance is very different. FIC10401 showing good 97%, while LIC10404 showing good 21%. Need visible ranking reason and include severity, criticality and persistence. Confidence alone does not tell which loop needs action first.
Green GOOD badge, green performance bar and red confirmed diagnosis can appear together. They may refer to different things, but labels are not clear. Separate signal quality, control performance and diagnostic condition.
Trend presentation can hide actual problem. FIC10401 is showing confirmed oscillation, but overview trend looks almost flat because PV around 800 is plotted on wide scale and OP around 29 is near bottom. Need useful scale for PV/SP and separate percentage scale for OP.
Other loops have PV and OP with similar numeric values, so plotting them together can look reasonable even though units are different. Every axis needs proper units and clear signal assignment. Shaded envelope also needs explanation.
Loop Explorer has rolling 8-hour trend, but older data is not convenient to access from same view. Add time presets, custom dates and previous/next period controls. Opening Historical should carry same loop and period.
Live trend and evaluated evidence are different time ranges. Make this distinction more visible. When clicking diagnosis, user should be able to open the exact evaluated period directly and compare it with current condition.
Evidence pages are too long and have nested scrolling. There is also horizontal overflow and long text extending across screen. Important conclusion should stay visible while detailed evidence is expanded below it. Avoid making user scroll through several sections to find reason.
Too much internal wording is exposed: ARGMAX_RANKED, qualified_support, disqualifier codes and long machine explanation strings. Main explanation should use engineering language. Raw identifiers and method details can stay under advanced information.
Numeric values are shown with unnecessary precision, like scores with many decimal places and support duration in milliseconds. Use sensible rounding and readable time units. Full precision can remain in export.
Red cross is being used for confirmed condition and STRONG evidence as well as failed/excluded checks. These meanings should be clearly different. Use readable labels and consistent symbols so user does not have to open each gate to understand it.
Some unavailable or excluded calculations are presented as 0.00. For example, excluded-mode comparison shows several zero metrics. Need distinguish measured zero from not calculated, not applicable and insufficient evidence. Otherwise user can read missing calculation as actual performance result.
Recent-window buttons have repeated labels like “Oct 5 · EXCLUDED MODE”. Need end time and duration on each button. Same date and status are not enough to identify which window user is opening.
“Why this result” sometimes repeats that engine judged the result. Need actual explanation: measured value, threshold, evidence that supported conclusion and limitation that remains. Also separate observed oscillation from tuning being possible cause.
100% confidence needs clearer meaning. Workbench itself says scores are uncalibrated, while overview presents percentage confidence. If this is evidence score, call it evidence score and explain its meaning near result. Do not make it look like statistical certainty.
Empty pages need more helpful next step. System Response has no events/model for selected loop, and other pages ask to select loop again. Explain what is unavailable, why, and where user should go next. Unavailable actions should have reason visible.
Investigation notes are only available when an open event frame exists. User may still need to save a preliminary observation for a loop with insufficient evidence or no open event. Provide loop-level notes and allow linking them to an event later.
VP and other optional inputs need applicability configuration per loop. Not installed, not applicable, expected but unmapped and temporarily unavailable should be different states. Missing optional input should limit relevant diagnosis, not make whole loop look incorrectly configured.
HEALTH NOT CONFIGURED and CONFIRMED diagnosis are shown together. This does not automatically mean diagnosis is wrong, but app needs to explain what has been confirmed and what instrument-health information was unavailable. Same applies to green PASS statuses.
