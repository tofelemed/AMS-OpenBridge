## 2. Findings and risks

- **F1 — Gate Configuration is SuperAdmin-only at Marun.** `cpm-14` (v2.7.1) took every `cpm.config.*` permission from the other roles and
  nothing grants them back (checked in the scripts). Browser checks of Gate Configuration need a SuperAdmin; "two people" means two
  SuperAdmins, or one uses "Approve alone" (recorded as a self-approval).
- **F2 — a deployed gate configuration can be lost at a later fresh Flink start, while the screen still shows it as active.**
  PREPARE and APPLY share one Kafka key on a compacted topic; after compaction a newly started job answers the APPLY with `NOT_PREPARED`
  and ignores it. A jar with another catalogue hash rejects the old PREPARE (`CATALOGUE_MISMATCH`), with the same result. Confirmed in the code;
  seen on the lab. It is not new and **it does not block this deploy, because Marun has no bundles** (B4 checks that). It **blocks the 9
  operating regions** until it is fixed, because Marun has no Flink HA: any Docker restart is a fresh start.
- **F3 — log checks do not work at Marun.** The plant runs `SERVICE_LOG_LEVEL=Error` and cplm-api uses it, so lines such as `KPI daily:`
  and `Evidence retention:` never appear. This runbook checks the database instead (D4). The same is true of the log greps in older sheets
  and in `MARUN-DAILY-CHECK.md` 7b.
- **The engine code has run on the lab since 23 Nov; the exact jar file has not.** Nothing under `src/flink` changed after the lab's build
  (`91d9b2aa`).
- The swap is a fresh Flink start: 12 h verdicts pause about 11.7 h, 24 h verdicts about 23.7 h (13 Nov figures). CHG-226 keeps the last
  real result on screen **only if one ended within one window length before the swap**. The jobs were restarted on 24 Nov, so deploying
  too soon leaves those loops on "Not enough data" (B3 decides).
- The generated `VM-STEPS.md` says "7 x RUNNING" in step 8 (correct: **8**), appends `PLANT_DAY_START` without checking that `.env` ends with a
  newline (C4 does), and runs `deploy.sh` twice (C7 runs it once). Frontend host port at Marun: **8090**.
