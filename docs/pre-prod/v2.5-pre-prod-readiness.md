## 3. Will the system work with the same OT payload? — Yes

The v2.5 ingestion parses exactly today's envelope (`value, unit, quality, ts, source, seq, device, area, line, site,
process_unit, equipment, item`). Frozen 1.0 fields of the Kafka tuple are byte-identical; `roles{}` is appended after them;
Flink's `TupleCodec` reads 1.1 and synthesises roles for 1.0; the old `ams-api` historian consumer ignores the block.
Three behaviour changes, none of which needs a gateway change:

1. **Quality.** `"GOOD" | "UNCERTAIN" | "BAD"` (case-insensitive) decode as before. **Anything else — absent, `"Good_NonSpecific"`,
   a number — is `UNKNOWN`, which fails G0** (`QUALITY_UNKNOWN`). Today the gateway sends `"GOOD"`; confirm the vocabulary it
   sends on OPC bad/uncertain quality (request O1 in the OT document).
2. **Non-finite values** (`NaN`, `Infinity`, overflow) are dead-lettered instead of being fed to the joiner.
3. **Per-role time and holds are visible.** A VP held for > 60 s (`G11.instrument_verified_max_age_s`) is no longer positioner
   evidence; a MODE that never arrived is `UNKNOWN` and excludes the window on G1 (as before).

Optional for the payload (nothing required): `VP` leaf for loops with positioner feedback (`param_roles` maps it by default),
`unit` (shown on axes), `SV`/`MV` aliases accepted. The `diagnostics` group duplicates `PIDParams` — subscribe one only (today: `PIDParams`).

## 6. Risks carried into the release (decide, do not discover)

| # | Risk | Mitigation / decision |
|---|---|---|
